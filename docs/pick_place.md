# 픽앤플레이스 (`motion/pick_place.py`)

책상 위 물체를 집어 다른 XY에 내려놓는 시퀀스다. GUI와 YOLO는 이 파일에 없다. 펜던트 **픽앤플레이스** 버튼이 단계를 만들어 `PickPlaceRunner`에 넘긴다.

호출은 `pendant/teach_grasp.py`의 `start_pick_place()`이다. 버튼은 50ms마다 `tick()`을 호출하고, 상태 줄에 지금 단계 이름을 쓴다.

같은 창의 **픽앤플레이스(유저생성)** 은 이 시퀀스를 타지 않는다. 프로젝트 루트 `user_pickandplace.py`의 `run(arm)`을, 펜던트가 이미 쓰는 컨트롤러에 붙여 실행한다.

## 1. 입력

좌표는 프로젝트 베이스이다. +X 앞, +Y 왼쪽, +Z 위. 위치는 mm, 자세는 roll·pitch·yaw(deg)이다.

| 인자 | 펜던트에서 오는 값 | 의미 |
|---|---|---|
| `p_xyz_mm`, `p_rpy_deg` | 물체 자세로 계산한 pre (`T_base`) | 대기 위치 P. 집기 직전 |
| `g_xyz_mm`, `g_rpy_deg` | 같은 계산의 grasp (`T_grasp_base`) | 집기 위치 G. pre에서 접근축으로 `a` mm 들어온 점 |
| `drop_xy_mm` | CAD yaml `drop.xy_mm`. 없으면 `(150, -100)` | 내려놓을 XY. Z는 받지 않는다 |

놓기 Z는 집기 Z와 같다. 놓기 자세는 집기 자세를 기준으로, TCP의 X축이 베이스 +X와 나란하도록 다시 잡는다. TCP X의 부호와 X축 180° 뒤집기는 집기 자세에 더 가까운 쪽을 고른다.

TCP 직선 단계의 속도는 펜던트 XYZ·회전 조그 슬라이더 값이다. 관절 속도%는 곱하지 않는다. 그리퍼와 초기자세, 드롭 XY의 관절 이동은 관절 속도를 쓴다.

## 2. 상수

`motion/pick_place.py` 위쪽이다. 그리퍼 폭을 바꾸려면 여기만 고친다.

| 이름 | 값 | 의미 |
|---|---|---|
| `PICK_LIFT_MM` | 30 | 집은 뒤 수직으로 드는 높이 |
| `PLACE_APPROACH_MM` | 50 | 놓기 위치 위 접근 높이 |
| `GRIPPER_OPEN_100` | 30 | 열기. 0이 닫힘, 100이 완전히 열림이라 30은 약간 연 상태 |
| `GRIPPER_CLOSE_100` | 0 | 닫기 |
| `STEP_PAUSE_S` | 1.0 | 한 단계가 끝난 뒤 다음 단계까지 대기. 0이면 바로 다음 |

높이는 집기 Z(`z_g`)에서만 만든다.

- 집기 리프트 `z_lift = z_g + 30`
- 놓기 접근 `z_hi = z_g + 50`
- 드롭으로 가로지를 때 높이 `z_xy = max(z_lift, z_hi)`

기본 상수에서는 가로지르는 높이가 `z_g + 50`이다. 집은 직후 30mm만 올라가므로, 드롭 위치로 갈 때 20mm를 더 올린다. `PICK_LIFT_MM`이 `PLACE_APPROACH_MM`보다 커지면 이미 더 높이 있으므로, 드롭 XY 다음에 **드롭 위** 단계가 하나 끼어 `z_hi`까지 TCP 직선으로 내려온 뒤 하강한다.

## 3. 동작 순서

팔이 하는 일이다. 괄호는 `build_pick_place_steps()`가 붙이는 단계 이름이다. 한 단계가 끝나면 1초 쉬고 다음으로 간다.

**집기.** 물체 자리에서 집는다.

1. 대기 위치 P로 간다. 자세는 집기 자세다. (P)
2. 그리퍼를 30까지 연다.
3. 집기 위치 G로 내려간다. 자세는 그대로다. (G)
4. 그리퍼를 0으로 닫는다.
5. 그 XY에서 30mm 들어 올린다. 자세는 집기 자세 그대로다. (집기 리프트)

**옮기기.** 드롭 XY 위로 옮기며 내려놓을 자세로 바꾼다.

6. 드롭 XY, 높이 `z_g + 50`으로 간다. 자세는 놓기 자세다. (드롭 XY)

**놓기.** 그 자리에서 내려놓고 빠진다.

7. 드롭 XY에서 집기 높이 `z_g`까지 내려간다. (하강)
8. 그리퍼를 30까지 연다.
9. 그 XY에서 50mm 들어 올린다. (놓기 리프트)
10. 펜던트 초기자세로 돌아간다. (초기자세)

```text
집기   P → 열기(30) → G → 닫기(0) → 위로 30mm
옮기기 드롭 XY, 위로 50mm, 놓기 자세
놓기   아래로 z_g → 열기(30) → 위로 50mm → 초기자세
```

## 4. 러너

동작 순서 자체는 위 목록이 고정이다. `PickPlaceRunner`는 그 목록의 인덱스만 넘긴다.

바깥 상태는 `idle`, `running`, `done`, `fault` 네 가지다. `running`인 동안 각 단계는 같은 순환이다.

```text
단계 시작 → 이동 중 → 1초 대기 → 다음 단계
```

마지막 단계의 이동이 끝나면 대기 없이 `done`이다. 상태 문자열은 `완료`이다.

- `start(steps)`가 첫 단계를 건다. 단계가 없거나 이미 `running`이면 `False`이다.
- `tick()`은 GUI 루프에서 부른다. 이동이 끝나기 전에는 같은 단계에 머문다.
- `abort()`는 제어를 멈추고 `fault`로 둔다.

이미 그 관절에 있으면 컨트롤러가 `이미 목표 관절에 있음`(`ALREADY_AT_TARGET`)을 내는데, 러너는 이것을 성공으로 본다.

`tick()` 도중 실패로 `fault`가 되는 경우:

- Stop이나 조그로 인터럽트가 바뀜. 상태 문자열 `중단 (Stop/조그)`
- 컨트롤러 fault (IK 실패, 충돌, go-to가 막힘 등). 그 문자열이 상태 줄에 그대로 간다
- 알 수 없는 단계 종류
- go-to가 시작되지 않음

펜던트는 `fault`이면 `픽앤플레이스 실패: ...`를 상태 줄에 표시한다.

**물체를 쥔 채 실패하면** (`그리퍼 닫기` 단계는 `hold=True`, 놓을 때 `그리퍼 열기`는 `hold=False` 로 컨트롤러의 「물체 쥠」을 바꾼다):

- 원인이 IK 실패 · 막힘 · 도달 못함이면 `build_safe_putdown_steps()` 로 바꿔 실행한다. 지금 x, y 에서 집은 높이까지 `SAFE_LOWER_MPS`(10 mm/s)로 내려가 → 그리퍼 열기 → `SAFE_LIFT_MM`(30 mm) 들기. 끝나면 `fault` 이고 상태는 `원인 → 물체를 내려놓고 멈춤`.
- 원인이 통신 오류 · E-stop · 제어 오류 · Stop 이거나, 내려놓기 중에 또 실패하면 더 움직이지 않고 `물체를 쥔 채 멈춤 — 손으로 받친 뒤 내려 주세요 (…)`.
- 「물체 쥠」 상태에서는 `start()` 가 거부한다 (첫 단계가 공중에서 그리퍼를 열기 때문).
