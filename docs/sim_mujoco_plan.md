# MuJoCo 시뮬레이션으로 브라켓 정합 실험하기 (노트북용 계획)

노트북에서 지금 실제 환경(2026-10-29 학생 책상)과 비슷한 장면을 MuJoCo로 만들고, 브라켓 자세 추정을
정답 6D와 비교하며 개선하는 계획입니다. 노트북의 Claude 에게 이 문서를 먼저 읽히고 시작합니다.
답변은 한국어로 합니다. 커밋 · 푸시는 사용자가 말할 때만 합니다.

## 왜 시뮬레이션인가

- 실제 장면에서는 브라켓의 진짜 6D를 모른다. 시뮬레이션은 **정답 6D를 정확히 안다** → 정합의
  위치 오차(mm), 회전 오차(°), 성공률, 시간을 숫자로 잴 수 있다.
- 바꿀 코드는 카메라 · 팔 없이 도는 `yolo/pose/register.py` 쪽이다. 실제 보드에는 브랜치로 가져간다.

## 지금 상황 요약 (Jetson 강의자 보드에서 확인한 값)

- 책상: 밝은 회색(은색). 로봇: 흰색 SO-101 7축. 브라켓: 흰색 하나만 쓴다 (`cad/bracket_4035.stl`, 42×35×42 mm).
- 지금 정합 흐름: YOLO 박스 + 자세 클래스(0 세우기 / 1 눕히기 / 2 비스듬히) → 박스 안 점군(책상 제거, 가장자리 튀는 점 제거)
  → 클래스 자세 + yaw 30° 간격 후보(12~24개)마다 ICP → 1등 → 중력 방향 맞춤.
- 실측(실제 점군 하나): 점 간격 1 mm 일 때 5~10 초 (오차 중앙값 0.69 mm), 2 mm 일 때 1.5~3 초 (1.11 mm).
- 문제: 느림, 가끔 틀림(겹침 0.3 대 실패, 90° 뒤집힌 답). 맞으면 정밀도는 충분.

## 장면 만들기 (MuJoCo)

`pip install mujoco` (노트북 AIvision 환경). 코드는 새 최상위 폴더 말고 `vision/sim/` 아래에 둔다.

| 요소 | 값 · 출처 |
|---|---|
| 좌표 | 프로젝트 베이스 = +X 로봇 앞, +Y 왼쪽, +Z 위, mm. URDF 좌표와는 `p_urdf = Rz(-90°) p_user` (`motion/base_frame.py`) |
| 책상 | z = 0 평면, 밝은 회색 |
| 로봇 | `motion/robot/SO101_6DOF.urdf` + `meshes/` (git 에 있음). 흰색. 관절은 `INIT_POSE_JOINTS_DEG` (`motion/robot_kinematics.py`) 등 |
| 브라켓 | `cad/bracket_4035.stl` (mm), `cad/model.yaml` 의 `mesh_rpy: [180, -90, 0]` 로 위를 맞춤. 흰색. 1~3개를 떨어뜨려 물리로 눕힌다 (자세가 자연스럽게 섞임) |
| 카메라 해상도 | 640 × 480. 컬러와 뎁스는 같은 내부값 (뎁스는 컬러에 정렬해서 쓴다) |
| 카메라 내부값 (180° 돌린 영상 기준, 코드가 쓰는 값) | fx = fy = 454.32, cx = 312.46, cy = 236.17 → MuJoCo fovy = 2·atan(240/454.32) ≈ 55.7° (주점 차이는 렌더 후 무시하거나 이미지 이동으로 보정) |
| 카메라 위치 `T_base_cam` (mm, 아래 행렬) | OpenCV 카메라 좌표(+z 앞, +y 아래). MuJoCo 카메라는 −z 앞, +y 위이므로 x 축 기준 180° 돌려서 넣는다 |

`eye_to_hand.json` 을 복사해 오거나, 위 값으로 같은 형식 파일을 만든다.

## 뎁스를 실제처럼 (Orbbec 흉내)

MuJoCo 뎁스는 완벽하다. 실제처럼 만들어야 정합 시험이 의미가 있다.
- 거리 노이즈: 가우시안 σ ≈ 1~2 mm (45 cm 기준).
- 가장자리 튀는 점: 물체 · 책상 경계 1~2 픽셀에 앞뒤 사이 중간 깊이.
- 구멍: 경계와 비스듬한 면에 군데군데 0 (값 없음).
- 위 셋은 켜고 끌 수 있게 (노이즈 없을 때 맞는지 먼저 확인).

## 할 일 (순서)

1. 장면 + 렌더: 컬러 png, 뎁스(mm, float32) npy, 정답(브라켓마다 T_base_obj, 자세 클래스) json 저장.
   물체마다 분할 마스크도 저장 (YOLO 박스 대신 쓴다. 박스 = 마스크 외접 사각형).
2. 기준 측정: 지금 코드(`yolo/pose/instances.py` `collect_instances` → `yolo/pose/register.py` `register_pose`)로
   장면 50~100개 → 성공률, 위치 · 회전 오차, 시간. 대칭(브라켓 좌우 대칭)은 같은 답으로 친다.
3. 개선 (추가 학습 없이):
   - 거칠게 → 정밀하게: 후보 고르기는 2~3 mm 점, 1등만 1 mm.
   - yaw 후보 줄이기: 위에서 본 점군의 최소 외접 사각형 방향 기준 0/90/180/270° 근처만.
   - 자세를 점군으로 판단 (YOLO 자세 클래스 없이): 놓인 높이 세우기 42 / 눕히기 35 / 비스듬히 32 mm + 윗면 기울기(수평/45°).
     애매하면 두 자세 다 시험. → YOLO 는 박스만(흰 브라켓 1클래스).
   - 학습 없는 물체 찾기: 책상 위로 튀어나온 점을 덩어리로 나눠 물체 하나씩 (YOLO 비상 경로).
4. 같은 장면으로 다시 측정 → 전후 표.
5. (선택) 로봇 마스크: 관절 각도 + URDF + T_base_cam 로 로봇이 보이는 픽셀을 지워 흰 로봇을 물체로 잡지 않게.

## 실제 보드로 가져갈 때

- 작업은 브랜치에서. 학생 보드는 `main` 만 받는다 (`deploy/update_board.sh`).
- YOLO 새 데이터 · 가중치는 기존 것(`yolo/datasets/raw`, `yolo/weights/best.pt`, 자세 3클래스)과 다른 경로에 둔다 (git 밖이라 브랜치로 안 갈린다).
- 실제 장면에서 한 번 더 확인: 자세 판단 높이 기준값, 노이즈 크기.
