# 가이드 · PPT 수정 목록 (최종 점검 때 한꺼번에)

최종 점검 = Word 파일 (`강사_가이드.docx`, 클라우드 Word 에서 고친 것) 과 `가이드/*.md` 를 비교해 맞춘 뒤, 아래를 반영하고 docx 를 다시 만든다.
⚠ docx 를 다시 만들면 Word 에서 고친 내용은 사라진다 → Word 에서 고친 것은 먼저 md 로 옮긴다.

## 1. 4차시 (`03_4차시.md`, PPT 4차시)

- [ ] 화면 180° 회전 반영: 렌즈 중심 cx′ = 315.1, cy′ = 235.5 (`intrinsics_for_rotate180`) 메모 추가
- [ ] 계산 예시 교체: 중심에서 오른쪽 100 px · 위 50 px → (415, 185) → 로봇 기준 (77, −39, 350) mm. PPT 4-6 · 4-10 예시도 같이
- [ ] 「사진 중심」 → 「렌즈 중심 (cx, cy)」 (77번째 줄 등)
- [ ] 카메라 원점 = 컬러 렌즈의 렌즈 중심 (광학 중심)
- [ ] 카메라 축 표 추가: OpenCV 약속 (X 오른쪽 · Y 아래 · Z 앞), 오른손 법칙, Y 가 아래인 이유, Z = 깊이 (직선거리 아님)
- [ ] 세로 픽셀 크기 = Z ÷ fy (가로는 Z ÷ fx). 300 mm → 0.66 mm, 350 mm → 0.77 mm
- [ ] K 표 다시 쓰기: fx · fy = 픽셀 단위 배율 (+ 화각 약 70.4° × 55.8°), cx · cy = 광축이 지나는 픽셀, dist = 실제 k1 0.0476 · k2 −0.0650 · p ≈ 0, 가장자리에서 2~3 px 정도
- [ ] leave-one-out 문장: 「사진 한 장씩 빼고 다시 풀었을 때 카메라 위치가 가장 많이 바뀐 거리」 (이상치를 뺀 남은 사진으로 계산)
- [ ] 「카메라 방향이 틀어진 것」 → 「계산된 카메라 방향 (extrinsic 의 회전) 이 실제와 조금 다른 것」 으로. 카메라가 기울어 달린 것 자체는 괜찮다 (캘리브가 계산에 넣는다). 원인은 ① 사진이 부족해 계산이 덜 맞음 ② 캘리브 뒤에 카메라가 움직임
  - 검증 ② 「설명할 것」 (약 233번째 줄)
  - 42번째 줄 「카메라 방향 1° → 약 8 mm」 → 「계산된 카메라 방향이 1° 틀리면」
  - 262번째 줄 문제 해결표 ③ 은 원인 ② 이야기라 그대로 둔다
- [ ] 검증 세 가지 짧은 소개 문단 (① 계산 숫자 · ② 책상 높이 · ③ 팔 끝) — Word 에 넣었다면 md 로 옮긴다
