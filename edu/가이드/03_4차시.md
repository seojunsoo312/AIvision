# 3.4 4차시 — 카메라와 손눈 캘리브 + 검증 (60분)

## 목표

- 카메라가 보는 것 (컬러 · 깊이) 을 안다.
- **왜 캘리브레이션을 하는지** 안다.
- 손눈 캘리브레이션을 직접 하고, **계산 숫자 · 책상 높이 · 팔 끝** 세 가지로 맞았는지 검증한다.

## 시간 배분

| 분 | 활동 | 명령 |
|---|---|---|
| 0–5 | 카메라가 보는 것: 컬러 · 깊이 | `vision_test.py` |
| 5–10 | **왜 캘리브레이션을 하나** | PPT 4차시 3~4 |

> 이 차시는 넘치기 쉽다. 통과 못 한 자리는 점심 시간을 조금 쓰거나 예비 캘리브로 바꾼다 (⏱ 참고). **모두 YOLO 없이 된다** (아직 학습 전이고 `box_best.pt` 도 없다).

## 0–5 카메라가 보는 것

오른쪽 위 칸 (vision):
```bash
python handeye/vision_test.py
```
(오른쪽 아래 칸이면 `python vision/handeye/vision_test.py`.)

**설명할 것**
- 카메라는 두 가지를 본다: 컬러 사진, 점마다 카메라까지의 거리 (깊이). 깊이 화면의 색 = 거리

⚠ 카메라를 쓰는 명령은 **한 번에 하나만** 켠다. Orbbec Viewer 가 켜져 있으면 끈다. 확인 뒤 `q`.

## 5–10 왜 캘리브레이션을 하나

**설명할 것**
- 카메라는 "사진의 (320, 240) 픽셀" 로, 로봇은 "베이스에서 앞으로 200 mm" 로 말한다 → 말이 다르다
- 둘 사이의 **번역표** 를 만드는 것이 캘리브레이션. 두 단계:
  - **렌즈 내부 값**: 픽셀 하나가 실제로 어느 방향인지
  - **손눈 캘리브레이션**: 카메라가 로봇 기준 어디에, 어느 방향으로 달려 있는지
- 조금만 틀려도 문제: 카메라 방향 **1°** → 45 cm 아래 책상에서 약 **8 mm** 어긋남 → 그리퍼 여유는 몇 mm 라 집기가 빗나감 → 그래서 **검증까지** 한다
- 카메라를 옮기면 번역표가 틀린다 → 받침을 건드리지 않는다

★ 시연 (강사 보드, 수업 전에 손눈 캘리브 · 학습을 해 둔 경우만): 카메라 받침을 살짝 돌려 놓고 「물체 위치 불러오기」 → 팔 끝이 브라켓 옆으로 가는 것을 보여 준 뒤 원래대로 돌린다. 학생 보드는 아직 물체 인식 창 (`roi_cloud.py`) 이 켜지지 않는다 (`box_best.pt` 없음). 미리 찍은 영상으로 대신해도 된다.

## 10–20 렌즈 내부 값 · 손눈 개념

```bash
python handeye/get_intrinsic.py
```
카메라에 저장된 공장 값을 읽어 저장한다 (한 번만, 금방 끝난다). 화면에 이런 줄이 나온다 (숫자는 카메라마다 다르다):
```
fx=453.518  fy=453.518  cx=323.899  cy=243.483

```

### 내부 파라미터 (intrinsic) 읽기 — 행렬 K

`vision/calib_data/intrinsics.json` 의 `camera_matrix` 가 3×3 행렬 K 다. 읽을 숫자는 네 개뿐이다 (나머지 0 · 1 은 자리 채움).

```
[ fx   0   cx ]     [ 453.5    0     323.9 ]
[  0  fy   cy ]  =  [   0    453.5   243.5 ]
[  0   0    1 ]     [   0      0       1   ]
```

| 숫자 | 뜻 | 읽는 법 |
|---|---|---|
| `cx`, `cy` | 렌즈 정중앙이 찍히는 픽셀 | 640×480 사진의 한가운데 (320, 240) 근처면 정상 |
| `fx`, `fy` | 확대 정도 (초점 거리를 픽셀로) | 거리 Z 에서 **픽셀 하나 = Z ÷ fx mm** |
| `dist` | 렌즈가 사진 가장자리를 휘게 하는 정도 | 0 에 가까울수록 덜 휜다 |

**설명할 것** (PPT 4차시 6)
- 내부 파라미터 = **카메라 · 렌즈 자체** 의 값. 카메라를 옮겨도 바뀌지 않는다
- 하는 일: 사진 속 한 점 (픽셀) + 그 점까지의 거리 (깊이) → 그 점의 **카메라 기준 3D 위치** (mm)
- 생각하는 순서: ① 사진 중심 (cx, cy) 에서 몇 픽셀 떨어졌나 → ② 그 거리에서 픽셀 하나가 몇 mm 인가 → ③ 둘을 곱하면 중심에서 몇 mm 떨어졌나

픽셀 (u, v), 깊이 Z (mm) → 카메라 기준 위치 (X 오른쪽, Y 아래, Z 앞):

$$X = \frac{(u - c_x) \times Z}{f_x}$$

$$Y = \frac{(v - c_y) \times Z}{f_y}$$

$$Z = 깊이$$

분수의 뜻: 거리 Z 에서 **픽셀 하나의 크기** 는

$$픽셀 하나 = \frac{Z}{f_x}$$

책상까지 약 350 mm 면 350 ÷ 453.5 ≈ **0.77 mm**. 브라켓 중심을 3픽셀 잘못 잡으면 약 2 mm 빗나간다.

예: 사진 중심에서 **오른쪽으로 100픽셀** 떨어진 점 (u = 424, v = 243), 깊이 350 mm

$$X = \frac{(424 - 323.9) \times 350}{453.5} \approx 77 mm$$

$$Y = \frac{(243 - 243.5) \times 350}{453.5} \approx 0 mm$$

$$Z = 350 mm$$

→ 카메라에서 보면 "오른쪽 77 mm, 앞 350 mm" 에 있는 점. 다만 이것은 아직 **카메라 기준** 이라 로봇이 못 알아듣는다 → 그래서 손눈 캘리브가 필요하다.

**설명할 것** (PPT 4차시 7, 그림)
- 팔 끝에 체스판 같은 보드를 붙이고, 팔을 여러 자세로 옮기며 사진을 찍는다
- 사진마다 두 가지를 안다: 카메라가 본 보드 위치, 팔이 알려 주는 팔 끝 위치
- 20장쯤 모으면 "카메라가 어디 있어야 둘이 모두 맞는지" 를 계산할 수 있다

### 외부 파라미터 (extrinsic) 읽기 — 행렬 T_base_cam

같은 출력의 `T_base_cam` (4×4) 이 손눈 캘리브의 결과, 곧 **번역표** 다. `vision/calib_data/eye_to_hand.json` 에 저장된다. 아래는 예시 숫자 (보드 · 자리마다 다르다):

```
       카메라 x   카메라 y   카메라 z  │ 위치
     [  0.036    -0.996    -0.076   │ 167.5 ]   ← 로봇 X (앞)
     [ -0.999    -0.036    -0.001   │ -10.8 ]   ← 로봇 Y (왼쪽)
     [ -0.002     0.076    -0.997   │ 347.6 ]   ← 로봇 Z (위)
     [  0         0         0       │   1   ]   ← 계산용 줄, 무시
```

**① 맨 오른쪽 열 = 카메라가 있는 자리** (mm, 로봇 베이스 기준). 출력의 `카메라 원점 in base mm` 줄과 같다.
예: (167.5, −10.8, 347.6) → 베이스에서 **앞으로 168 mm, 오른쪽으로 11 mm, 높이 348 mm**.

**② 왼쪽 3×3 = 카메라가 향한 방향.** **세로 (열) 로** 읽는다. 각 열은 "카메라의 이 축이 로봇 기준으로 어느 쪽을 향하나". 1 이나 −1 에 가까운 칸만 보면 된다.

| 열 | 카메라 축 | 큰 값이 있는 칸 | 뜻 |
|---|---|---|---|
| 1열 | x (사진의 오른쪽) | 로봇 Y 줄에 −0.999 | 사진 오른쪽 = 로봇 **오른쪽 (−Y)** |
| 2열 | y (사진의 아래쪽) | 로봇 X 줄에 −0.996 | 사진 아래쪽 = 로봇 **뒤 (−X, 베이스 쪽)** |
| 3열 | z (카메라가 보는 방향) | 로봇 Z 줄에 −0.997 | 카메라는 **아래를 본다** |

**설명할 것** (PPT 4차시 10)
- 외부 파라미터 = **카메라를 놓은 자리와 방향**. 카메라를 옮기면 다시 구해야 한다
- 오른쪽 열 = 위치, 왼쪽 3×3 = 방향 (세로로 읽기). 맨 아래 줄 `0 0 0 1` 은 계산용이라 무시
- 3열이 정확히 −1 이 아니라 −0.997 → 카메라가 똑바로 아래에서 약 4° 기울어 있다는 뜻
- 활동: 자로 베이스 중심에서 카메라까지 앞 · 옆 · 높이를 재서 ① 의 숫자와 비교 (몇 cm 안이면 큰 실수는 없다. 정확한 확인은 검증 ② · ③)

강사 참고 — 두 행렬을 이어 쓰는 예 (질문이 나오면): 사진 정중앙 픽셀 (324, 243) 에서 깊이 350 mm
1. K: 정중앙이므로 카메라 기준 (0, 0, 350) — 보는 방향으로 똑바로 350 mm
2. T: 카메라 위치 + 3열 × 350 → X = 167.5 − 0.076 × 350 ≈ **141**, Y = −10.8 − 0.001 × 350 ≈ **−11**, Z = 347.6 − 0.997 × 350 ≈ **−1.4** mm
3. 베이스 앞 141 mm, 높이 약 −1 mm = 책상 (검증 ② 의 책상 높이 약 −2 mm 와 맞다)

픽셀 → (K) → 카메라 기준 3D → (T) → 로봇 기준 3D → 팔이 그 좌표로 간다.

### 검증 ① 숫자 읽기

화면에 나오는 숫자 중 볼 것 (**검증 ①**):

| 출력 줄 | 뜻 | 통과 기준 (안) |
|---|---|---|
| `사용 n/m장, 제거 k장` | 계산에 쓴 사진 수 | 15장 이상 |
| `tcp-보드 residual mm mean/max` | 사진마다 어긋난 정도 (평균 / 최대) | 평균 3 이하, 최대 8 이하 |
| `tcp-보드 residual deg mean/max` | 방향 어긋남 | 참고 |
| `leave-one-out T 변화 mm max` | 사진 한 장을 빼고 다시 풀었을 때 결과가 움직인 정도 | 3 이하 |

**설명할 것**
- 「한 장 빼고 변화」: 사진 하나를 빼고 다시 풀어도 결과가 거의 같으면 사진이 충분하고 고르다. 많이 바뀌면 특정 사진에 기대는 것 → 더 찍는다

### 팔 캘리브 자동 점검 · 보정 (compute.py 가 이어서 한다)

`compute.py` 는 손눈 계산이 끝나면 **같은 사진으로 팔 캘리브 (L 자) 가 틀어졌는지** 점검하고, 틀어졌으면 고칠지 묻는다 (10~30초, `== 팔 관절 0° (캘리브 L자) 점검 중...`). 따로 할 일은 없다.

**설명할 것**
- 팔 캘리브는 처음에 팔을 L 자로 놓고 그 자세를 관절 0° 로 정했다. 눈으로 맞춘 L 자라 **몇 도씩 틀어질 수 있다**
- 관절이 틀어지면 팔이 알려 주는 팔 끝 위치가 틀린다 → 그 값으로 푼 손눈 결과도 몇 mm · 몇 도 어긋난다 → 집기가 빗나간다
- 보드는 팔 끝에 고정돼 있으니, 관절 값이 맞으면 모든 사진에서 "팔 끝에서 본 보드 위치" 가 같아야 한다 → 사진들이 가장 잘 맞도록 관절마다 몇 도를 더할지 계산한다 (S2 ~ S5)
- **팔은 움직이지 않고, 사진도 다시 찍지 않는다.** 팔로워 캘리브 파일과 손눈 결과를 함께 고친다

나오는 메시지와 할 일:

| 메시지 | 뜻 | 할 일 |
|---|---|---|
| `팔 관절 0°: 이미 잘 맞습니다` 또는 `… 고칠 것이 없습니다` | 틀어짐이 작다 | 없음 |
| 관절별 오차 표 → `… 고칠까요? 팔은 움직이지 않습니다. (y/N)` | 틀어짐을 찾았고 믿을 만하다 | **`y`**. 이어서 손눈을 다시 계산한다 |
| `팔 캘리브는 고치지 않음: 사진 절반씩 푼 값이 … 다릅니다` | 사진이 다양하지 않아 답이 흔들린다 | 자세를 더 다양하게 (좌우 · 손목 꺾기 · 높낮이) 더 찍고 다시 |
| `… 고치지 않음: 오차가 … 너무 큽니다` | 15° 넘게 틀어짐. 자동으로 고치기엔 너무 크다 | 쉬는 때 팔 캘리브를 다시 (`bash deploy/calibrate_arms.sh`) |
| `… 고치지 않음: 보정해도 오차가 충분히 줄지 않습니다` | 관절 문제가 아니다 | 보드가 팔 끝에서 흔들렸는지, 카메라 받침이 움직였는지 확인 |
| `… 고치려면 펜던트를 끄고 다시 실행하세요` | 펜던트가 팔을 쓰고 있다 | 펜던트를 닫고 `compute.py` 다시 |

`y` 로 고친 뒤:
- 화면 끝 「확인할 것」 의 1번: 펜던트 Connect → **HOME** 이 반듯한 L 자인지 본다.
- 2번 (카메라 창 `r`) 은 아직 물체 인식 창이 안 켜지므로 건너뛰고, 대신 **검증 ② · ③** 으로 확인한다.
- 고치기 전 캘리브 파일과 사진 기록은 자동으로 백업된다 (경로가 화면에 나온다). 되돌리는 법도 화면에 나온다.

기준은 이전 캘리브 기록 (좋은 자리 residual 평균 1.7 mm, 한 장 빼고 변화 최대 2.4 mm) 으로 잡은 **안** 이다 **[실물 확인]**.

| 볼 숫자 | 뜻 | 통과 기준 (안) |
|---|---|---|
| `평균 z_base` | 보드 코너들의 로봇 기준 높이 | 책상 높이 (약 −2 mm) ± 3 mm |
| `min` ~ `max` | 코너끼리 높이 차 | 4 mm 이하 (기울어진 캘리브면 한쪽이 높게 나온다) |
| `평균 depth−pnp` | 깊이 카메라와 사진 계산의 차 | ±5 mm 안 |

**설명할 것**
- 보드가 책상에 평평하니, 번역표가 맞으면 모든 코너 높이 = 책상 높이. 한쪽만 높으면 카메라 방향이 조금 틀어진 것

### 검증 ③ 팔 끝으로 코너 찍어 보기

1. 검증 ② 화면의 표에서 보드 코너 하나의 `x_base`, `y_base` 를 적는다.
2. 펜던트를 켜고 Connect → TCP 목표 입력칸에 X · Y 와 **Z = 20** 을 넣고 **TCP 이동** (노트북이면 `arm.moveL([x, y, 20], "abs")`).
3. 그리퍼 끝 바로 아래와 실제 코너 사이를 **자로** 잰다.
4. 다른 코너 하나 더.

통과 기준 (안): 두 코너 모두 **3~5 mm 안**.

⚠ 팔을 실제로 움직인다. **천천히, 책상 위 20 mm 이상에서만**. 보드에 닿게 내리지 않는다.

### 기록표

부록 8.6 「4차시 기록표」 에 학생마다 적는다: 사용 장 수, residual 평균 · 최대, 한 장 빼고 변화, `z_base` 평균 · 차, 코너 두 개의 어긋남 (mm). 7 · 8차시에 집기가 빗나갈 때 "캘리브 문제인지" 를 가르는 데 쓴다.

### 통과 못 하면

| 어디서 | 해볼 것 |
|---|---|
| ① residual 이 큼 · 한 장 빼고 변화가 큼 | 사진을 더 다양하게 (손목 기울기 · 화면 구석) 5~10장 더 찍고 다시 계산 |
| ① 사용 장 수가 적음 (많이 제거됨) | 보드가 흔들림 → 다시 단단히 붙이고 처음부터 |
| ② 한쪽이 높음 | ①과 같이 다양하게 더 찍기 |
| ③ 한 방향으로 일정하게 어긋남 | 카메라 받침이 흔들림 · 움직였는지 확인. 움직였으면 처음부터 |

## ⏱ 시간 조절

- 모자라면 (가장 흔함): 검증 ③ 을 강사가 대표로 한두 자리만. 촬영을 못 끝낸 자리는 점심 시간을 조금 쓰거나 **예비 캘리브** (검증 통과본, 카메라 받침이 같은 자리일 때만) 를 `vision/calib_data/` 에 넣는다.
- 남으면: ★ 카메라를 일부러 살짝 돌려 검증 ②를 다시 → 숫자가 얼마나 나빠지는지 보고, 원래대로 돌린 뒤 다시 캘리브 (돌린 뒤에는 반드시 다시 해야 한다).
