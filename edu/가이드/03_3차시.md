# 3.3 3차시 — 코드로 움직이기 (60분)

## 목표

- 노트북 칸을 위에서부터 한 번씩 실행하는 법을 안다.
- `moveL` (그리퍼 끝을 곧은 선으로) 과 `moveJ` (관절을 돌려서) 의 차이를 안다.
- 상대 이동 `"rel"` · 절대 이동 `"abs"` · 지금 위치 읽기 `where()` 를 쓴다.
- 가상 팔에서 확인한 코드를 실물 팔로 다시 실행한다.

## 시간 배분

| 분 | 활동 | 노트북 | PPT |
|---|---|---|---|
| 0–15 | 노트북 열기, 팔 켜기, 시작 자세 | 시작 전에, 1 · 2절 | 3차시 2 |
| 15–40 | `moveL` · `moveJ`, 상대 · 절대, `where()`, 관절, 홈 | 3~7절 | 3차시 3~7 |
| 40–60 | 가상 → 실기 | 10 · 11절 → 1~7절 | 3차시 8 |

**8 · 9절은 오늘 하지 않는다.** 8절 · 8-2 · 8-3 은 7차시, 9절 · 9-2 · 9-3 은 8차시에 쓴다. 7절이 끝나면 10절로 건너뛴다.

### 노트북 두 가지

| 파일 | 학생이 하는 일 | 쓰는 때 |
|---|---|---|
| `로봇 제어 실습.ipynb` (완성본) | 실행만 한다 | 처음 코딩하는 반, 시간이 모자랄 때 |
| `로봇 제어 실습_빈칸.ipynb` (빈칸본) | `# 빈칸채우기` 가 붙은 줄의 괄호 · 대괄호 안을 채우고 실행한다 | 기본 문법을 아는 반 |

- 두 노트북의 절 번호 · 순서 · 코드는 같다. 빈칸본은 칸 설명 끝에 「할 일」 한 줄이 더 있다.
- 빈칸본은 15–40 이 10분쯤 더 걸린다 (⏱ 시간 조절).
- 막힌 학생은 완성본의 같은 칸을 보면 된다 (같은 보드에 둘 다 있다).

## 0–15 노트북 열기와 첫 이동

### 준비

⚠ **펜던트를 끈다.** 노트북과 펜던트는 같은 팔을 동시에 쓸 수 없다.

```bash
conda activate AIvision
cd ~/AIvision
jupyter notebook "로봇 제어 실습.ipynb"
```

빈칸본은 파일 이름만 `로봇 제어 실습_빈칸.ipynb` 로 바꾼다.

VS Code 로 열어도 된다. 이때 오른쪽 위의 커널이 **AIvision** 인지 확인한다. 다른 이름이거나 「커널 선택」 이면 눌러서 **AIvision** 을 고른다.

**설명할 것** (PPT 3차시 2)
- 노트북은 칸 (셀) 단위. **Shift + Enter** = 실행하고 다음 칸으로.
- 칸 왼쪽이 `[*]` 이면 실행 중이다. 이동 명령은 팔이 도착할 때까지 `[*]` 로 기다린다.
- 반드시 **위에서부터 한 번씩**. 「1절 팔 켜기」 를 두 번 실행하면 팔이 겹친다 → 커널 재시작 후 1절부터.
- 「시작 전에」 칸의 약속을 같이 읽는다: +X 앞 · +Y 왼쪽 · +Z 위, 위치는 mm, 자세는 도 (2차시 복습).

Python 을 처음 보는 학생 대응은 4장.

### 1절 팔 켜기

```python
from motion import Arm, load_pick_targets
arm = Arm()                 # 가상 팔. 3D 화면이 브라우저에 뜬다
print(arm.where())
```

- 브라우저가 안 열리면 출력된 `Meshcat` 주소를 연다.
- `where()` 결과를 같이 읽는다: `joints_deg` (관절 6개), `gripper` (0 닫힘 ~ 100 열림), `xyz_mm` (그리퍼 끝 위치), `rpy_deg` (자세).

### 2절 시작 자세와 그리퍼

```python
arm.initial()               # 작업을 시작하는 자세. 그리퍼는 닫힌다
arm.grip(100)               # 그리퍼 완전히 열기 (0 = 닫힘)
print(arm.where())
```

## 15–40 moveL · moveJ, 상대 · 절대, 지금 위치

### `moveL` 과 `moveJ` (3절 전에)

**설명할 것** (PPT 3차시 3)

| | `moveL` | `moveJ` |
|---|---|---|
| 정하는 것 | 그리퍼 끝 좌표 (mm) | 관절 각도 (도) |
| 그리퍼 끝이 가는 길 | 곧은 선 | 둥근 선 |
| 쓰는 때 | 내려가기 · 들어 올리기 | 멀리 옮기기 (관절에 무리가 적다) |
| 속도 `speed` | mm/s, 기본 25 (5~45) | 도/s, 기본 24 (8~45) |

### 3~7절

한 절씩 학생이 실행하고, 3D 화면에서 움직임을 본 뒤 다음 절로 간다.

| 절 | 코드 | 짚을 것 |
|---|---|---|
| 3 상대 이동 | `arm.moveL([30, 0, 0], "rel", speed=10)` → `arm.moveL([0, 20, 15], "rel")` | `"rel"` 은 지금 위치에 **더한다**. 앞으로 30 mm (천천히), 그다음 왼쪽 20 · 위 15 mm |
| 4 절대 위치와 자세 | `arm.moveL([200, 0, 120], "abs")` → `arm.moveL([180, 40, 90], "abs", rpy=[0, 80, 0])` | `"abs"` 는 베이스 기준 **목표 좌표**. `rpy` 는 더하는 각도가 아니라 **목표 자세** |
| 5 지금 높이 읽어 올리기 | `x, y, z = arm.where()["xyz_mm"]` → `arm.moveL([x, y, z + 40], "abs")` | `where()` 로 읽은 숫자로 다음 목표를 만든다. 결과는 `"rel"` 로 위 40 과 같다 |
| 6 관절 | `arm.moveJ([0, -40, 40, 0, -90, 0], "abs")` → `arm.moveJ([0, 10, 0, 0, 0, 0], "rel", gripper=20)` | 관절 6개 (J1~J6, 도). 끝은 곧게 가지 않는다. `gripper=20` 은 그리퍼를 지금보다 20 더 연다 |
| 7 홈 | `arm.home()` | 관절이 모두 0 인 L 자. 그리퍼는 반쯤 열린다 |

**빈칸본을 쓰면** — 학생이 채우는 곳과 답

| 절 | 채우는 곳 | 답 |
|---|---|---|
| 2 | `arm.grip( )` | `100` |
| 3 | 두 번의 `[ , , ]` | `[30, 0, 0]`, `[0, 20, 15]` |
| 4 | 첫 줄의 mode, 둘째 줄의 `rpy=[ , , ]` | `"abs"`, `[0, 80, 0]` |
| 5 | `[x, y, ]` | `z + 40` |
| 6 | 둘째 줄의 mode | `"rel"` |
| 7 | `arm. ()` | `home` |

비운 채 실행하면 대부분 `SyntaxError` 로 칸 전체가 실행되지 않는다 (팔이 안 움직인다). 2절만 `initial()` 을 실행한 뒤 `TypeError` 가 나고, 5절은 `ArmError: xyz는 mm 3개입니다` 가 난다.

**확인 질문** (PPT 3차시 4)
- "`moveL([0, 0, 50], "rel")` 을 두 번 실행하면?" → 100 mm 올라간다.
- "`moveL([200, 0, 120], "abs")` 를 두 번 실행하면?" → 두 번째는 이미 거기라 안 움직인다.

## 40–60 가상 → 실기

**설명할 것** (PPT 3차시 8)
- 같은 코드를 실물로 돌린다. 실물은 부딪히면 다칠 수 있으니 강사가 "실기" 라고 한 뒤에만.
- 실행 전에 칸의 숫자를 짝과 같이 읽는다 (특히 `"abs"` 의 Z 가 책상 위인지, `"rel"` 의 크기).

### 순서

1. **가상 팔 끄기** — 10절 `arm.close()`.
2. **연결 확인** — 11절에서 `REAL = False` 를 `REAL = True` 로 바꾸고 그 칸만 실행한다. 실물 팔이 지금 위치를 출력하고, 초기자세로 간 뒤, 연결을 스스로 끊는다. 여기까지 되면 연결은 정상.
3. **실물로 1~7절** — 커널 재시작 (↻) → 1절의 `arm = Arm()` 을 `arm = Arm(mode="real")` 로 고친다 → 1절부터 7절까지 한 칸씩 다시 실행한다. ⚠ 처음에는 `speed=10` 을 붙여 천천히.
4. **끝** — 10절 `arm.close()` 를 실행하고, 1절을 다시 `Arm()` 으로 되돌려 둔다 (다음 차시는 가상 팔로 시작).

> 11절은 연결만 확인하는 칸이다. 11절 뒤에 바로 3절을 실행하면 팔이 이미 꺼져 있어 `ArmError` 가 난다. 그래서 3번처럼 1절을 고쳐서 다시 켠다.

### 멈추기

- 노트북에는 펜던트의 Space · Esc 가 없다.
- 위험하면 노트북의 **■ (중단)** 을 누른다 → 팔이 그 자리에서 멈추고 `ArmError: 중단 …` 이 뜬다. 다음 칸은 다시 실행하면 된다.
- ■ 로도 안 멈추면 팔을 받치고 전원을 끈다.

### 잘 되면

- 가상과 실물이 같은 칸에서 같은 곳으로 간다.
- 가상 팔에서 `where()` 의 `xyz_mm` 이 명령한 숫자와 같다 (소수점 차이 정도).

### 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| `NameError: name 'arm' is not defined` | 1절을 안 실행 | 1절부터 다시 (4.3) |
| 팔이 두 개 보임 · 이상하게 움직임 | 1절을 두 번 실행 | 커널 재시작 → 1절부터 |
| `ArmError: 이미 종료된 Arm 입니다` | 10절 · 11절 뒤에 다른 칸 실행 | 실기 순서 3번 (1절을 고쳐서 다시 켜기) |
| `ArmError: 실기 연결 실패 …` | 펜던트가 켜져 있음 · 케이블 | 펜던트 끄고 11절 다시 |
| `ArmError: 목표까지 … mm 남음 (도달 못함)` · `IK 실패 …` | 닿지 않는 좌표 · 자세 | 덜 멀리 · 덜 낮게. 오류 읽기는 7차시 (5.1, 부록 8.4) |
| `ArmError: speed는 5–45 mm/s 입니다` | 범위 밖 속도 | `moveL` 5~45, `moveJ` 8~45 |
| `TypeError: … missing … 'mode'` · `ArmError: moveL의 두 번째 인자는 …` | `"rel"` · `"abs"` 를 빠뜨림 · 오타 | `"rel"` 또는 `"abs"` 를 넣는다 |

## ⏱ 시간 조절

- 모자라면: 6절 (관절) 은 시연으로만, 실기는 3 · 4절만. 빈칸본으로 시작했으면 남은 절은 완성본으로 바꿔 실행만 한다.
- 남으면: "책상 위 네 점을 차례로 들렀다 오기" 를 `"abs"` 로 짜기 (Z 는 50 이상).
